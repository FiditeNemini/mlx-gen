## Context

Two reviewed waves ship together. The performance wave (0093 sequential weight
prefetch, 0094 default MLX buffer-cache limit, 0095 flux2 prompt/compile
caches) was committed on main as `9c1c59a` and sat UNRELEASED. The Wan
consistency wave (0097 `--last-image` EXPERIMENTAL bracket conditioning, 0098
prompt-truncation warning, 0099 explicit denoising step grids) completed a
three-cycle adversarial review (cycle-3 verdict GREEN: 1517 passed / 7
skipped, lint clean) and sits in the working tree on `b71bc4b`. The owner
explicitly ordered the release. The BlackPixel host adoption of the new
surfaces is gated on this release.

## Problem

0093/0094 touch EVERY family's weight-load path and 0098 rewrites the Wan
prompt-encode measurement path; ADR 0001 discipline requires one real
same-seed output-identity check against the previous release before the
release claims "no output change".

## What we want to do

Cut 0.25.0 through the standard release flow (docs/release.md tag path) with
smoke evidence recorded here.

## Smoke evidence (recorded 2026-07-25, TI2V-5B q8, 384x384, 9 frames, 2 steps, seed 42)

- Baseline: v0.24.0 worktree at `2b496bf` (`git worktree add --detach`,
  `uv sync --frozen`), dependency set IDENTICAL to the release tree (the
  0.25.0 lock diff is the package version line only). Candidate: the full
  0.25.0 release tree. Both runs used
  `mlxgen generate --model AbstractFramework/wan2.2-ti2v-5b-diffusers-8bit
  --prompt "a red ball rolling across a wooden table" --width 384 --height
  384 --frames 9 --steps 2 --seed 42 --no-prompt-cache` so both exercised
  the full UMT5 encode path (0098 rewrote its measurement path) instead of
  the shared prompt-embed disk cache.
- Verdict: raw-YUV comparison (the preserved /tmp/compare_videos.py from the
  0.24.0 release) reports frames=9 max_abs_yuv_diff=0 — BITWISE IDENTICAL.
  This covers the 0093 prefetch load path (bytes identical by design), the
  0094 default cache limit (buffer-cache bookkeeping only), and the 0098
  encode-path rewrite (token counting must not change embeds).
- Observed live: the candidate announced the 0094 default exactly as
  documented ("Applying default MLX cache limit: 8.0 GiB (total RAM / 8,
  clamped to [1, 8] GiB)...") — one stderr line, override flags named.
- Wall time: baseline 142 s, candidate 105 s end-to-end (second run benefits
  from page-cache warmth; not recorded as a measured 0093 speedup claim).
